# 高自由度的智能客服：用 AI 设计样式，按自己的业务配置工作方式

同一套在线客服系统进入不同运营商的网站，应该适应不同品牌、数据和日常工作。SRICH CHAT 把这种适应能力放在三个位置：会员看到的页面和卡片、客服看到的数据与操作、Runtime 执行的岗位流程。

## 从一句要求到可应用的样式

运营可以提出“沿用网站的深色背景，弱化边框，突出查询结果”这类要求，也可以提供参考。AI 助手在支持的页面定义里修改样式与结构，产出草稿，运营通过预览判断是否合适，再应用或发布。

消息、事件、邮箱与查询卡片也按各自支持的模板和字段配置。业务数据与展示分开后，接口不需要为了换一个颜色重新做一遍。

“对话生成样式”的价值，是减少运营描述、设计修改与研发排期之间的往返。它仍有支持范围：不能要求 AI 随意增加业务权限或生成任意脚本；不同卡片以对应编辑器支持的内容为准。

## 工作台跟着业务走

客服最需要先看见什么，不同网站不同。运营可以给已有看板字段起名称、排序、标记颜色，把重要值放到默认展示位置；还可以将已接入的业务操作配置成表单和按钮。

这些配置建立在对接方提供的接口之上。没有接口，看板不会凭空知道会员余额，操作也不会自己进入买方后台执行。

## 按前置来规划上线

| 能力 | 主要前置 |
| --- | --- |
| 网站、页面、客服、分组、快捷回复、权限等 | 运营在后台配置 |
| 看板、操作、知识源、事件、信息、红包、外部系统写邮箱、查询 | 买方开发配合，查询复用已有看板 |
| AI 员工、语义检索、翻译、AI 样式助手 | AI 服务配置及各自功能配置 |
| 图片与表情包相关能力 | 对象存储配置 |
| 查单员的上游协作 | Telegram Bot、群映射、业务接口与已发布流程 |

类别有重叠，不是三个可以直接相加的数量。比如查单员既需要 AI 与外部服务，也需要开发完成订单相关接口。

## 自由度最终服务于什么

会员得到与网站一致的服务入口；客服少切换后台；运营可以自己调整日常展示；开发集中提供可信业务能力。FAQ、Runtime、AI Agent 与人工协作承接真正的咨询和任务，样式只是把这些能力清楚地呈现给人。
