# SRICH CHAT 对接更新摘要：会员查询、信息与邮箱、决策层和限流

本篇汇总截至 2026-09-22 买方需要关注的对接变化。它是公开阅读摘要，不替代帮助中心的逐版本变更记录；实际功能以部署版本与启用配置为准。

## 事件与邮箱增加 429 处理

事件按网站和 action 限流，邮箱按网站的收信人数限流。调用方要读取 Retry-After 后再重发，保持 event_id。不要把 429 当成功，也不要立即循环请求。

这会影响重试代码，即使平时流量低，也应该在联调中覆盖。

## 会员在聊天里输入“/”查询

运营可以把已有看板开放给会员，会员选择查询后得到聊天卡片。买方接口仍是原看板请求，无需为此再建一套接口；但先有看板对接是前提，会员展示字段需单独确认。

## 信息与邮箱分开

信息传给网站页面，过期不补；邮箱和事件写入会员聊天，按消息保留策略保存。信息的技术路由仍使用 broadcasts。邮箱新增指定名单 notice 与 summary，运营主动写信与外部系统调用是两条使用方式。

## AI 判断与执行分开配置

知识候选与 AI 员工可以按配置放进同一道模型判断，以区分“问规则”和“要办事”。出厂规则与可选模型判断不同；启用前先比较效果。员工本身仍按已发布的固定流程执行。

## 翻译与看板显示

嵌入的 data-lang 除了界面，还提供会员阅读语言依据；翻译需要相应配置。看板 text 类型上限调整为 32 字符。它们不会自动替买方补齐业务字段或语言偏好。

## 统一修正一个易误解的说法

持续会话意味着同一会员能接续服务关系，不意味着所有历史永久保存。当前默认启用 30 天消息清理，具体按运营保留策略执行；通行证有效期、信息有效期、任务时限与消息保留期必须分开理解。

升级时先核对契约与启用配置，再回归身份、重复请求、异常与恢复。公开文章不能替代实际部署版本验收。
