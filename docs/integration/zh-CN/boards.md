# 客服数据看板与会员查询：一个接口如何支持两种使用场景

看板把会员在买方系统里的数据放到客服会话旁，避免复制编号和切换窗口。买方提供接口，运营配置字段、类型、显示名、颜色及默认展示位置。会员查询可以复用已接好的看板。

## 请求与响应

每个看板配置 HTTPS 地址及 Bearer 钥匙，客服系统 POST 当前会员的 `user_id`、`board`、`request_id`；列表型另带 `page` 和 `page_size`。页码从 1 开始，普通看板每页最多 50 行，超时 3 秒，普通查询不自动重试。

记录型返回 `code / msg / data`；列表型返回 `code / msg / list / page / page_size / total`。普通看板无数据用空对象或空列表，列表越界也返回空列表。AI 查单员的专用看板有更严格规则，不套用空记录惯例。

| 类型 | 值 |
| --- | --- |
| text | 最多 32 字符的非空文字 |
| money | 最小货币单位整数 |
| number | 安全范围内整数计数 |
| datetime | Unix 秒，不是毫秒 |
| event | amount_minor、state、at 三个键完整；state 为 success / pending / failed |
| flag | 需要标记时 true，不需要时不提供 |

只展示后台声明的字段，未声明的字段丢弃；敏感字段名受限制。分页采用稳定排序，total 是总条数而非当前页条数，不知道总数时不要编一个。

## 从客服看板到会员查询

运营在“查询”里开放某个已对接看板后，会员输入 `/` 选查询。仍调用同一地址和契约，会员编号来自可信身份，不接受命令指定另一个人。列表只展示第一页，最多 10 行；每位会员每分钟最多 5 次。

给会员展示的字段可与客服不同。买方的拒绝 `msg` 不直接传给会员；查询结果渲染成卡片写进会话，按消息保留策略保存。

## 数据与失败边界

客服常规看板响应不作为业务数据入库，有短时缓存；会员查询卡片和员工任务必要记录是不同场景，不能笼统宣传“什么都不存”。

默认展示取不到数据可能只是空白；客服主动打开看板才看到相应提示。请测试字段类型错误、毫秒时间、超时、分页边界与跨会员请求，不能只看页面能打开。专用订单及最终结果看板见员工能力篇。
