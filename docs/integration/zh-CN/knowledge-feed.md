# FAQ 知识库接入：不依赖 AI 的知识底座，如何同步与验收

FAQ 的权威内容在买方业务系统。你们提供当前有效的全量知识，客服系统按小时拉取并整批替换，也支持运营触发立即同步。没有 AI 服务仍可使用本地关键词检索；语义检索与员工判断是额外增强。

## 你们提供的接口

每站一个 HTTPS 地址和 Bearer 钥匙，客服系统发起 GET，不传会员数据，不跟随重定向，超时 10 秒。

```json
{"entries":[{"id":"faq-demo-1","title":"怎样查询处理进度","body":"请在会员中心查看当前记录，仍需帮助时联系客服。","category":"服务","language":"zh-CN","updated_at":1789948800}]}
```

| 字段 | 主要规则 |
| --- | --- |
| `id` | 站内稳定且唯一，1–64 字符，使用契约允许的字符 |
| `title` | 必填，1–200 字，写成会员会问的问题 |
| `body` | 必填，1–16000 字，放已认可答案 |
| `category` / `language` | 可选分类与语言 |
| `updated_at` | 可选 Unix 秒，未提供不能冒充更新时间 |
| `employee_entry` | 可选员工入口，含员工编号及可选按钮文案 |

最多 2000 条、响应体最多 8 MB。未知字段会导致整批拒收。标题加正文超过 4000 字的条目可保存，但只能用关键词检索；长规则应按问题拆分。

## FAQ 怎样连到 AI Agent

某条 FAQ 可以配置员工入口按钮。买方 feed 给的是默认值，运营后台按条目配置的值优先；员工未发布或停用时按钮不出现。

这让“问处理时效”和“要核查某笔记录”有不同结果：前者读规则，后者可从对应按钮进入固定任务。不要给所有 FAQ 都配置同一个办理入口。

## 同步失败不等于清空

接口失败、超时或一条内容不合规时，继续使用上次成功内容，后台记录失败原因。合法返回空 `entries` 才是清空知识库。

验收时分别测试正常全量、空列表、未知字段、长内容和失败后保留旧版本。内容上线后检查同步状态，不能因为会员端仍能回答就断言新规则已经生效。还要用真实问法检查答案与候选，拿不准的情况让人工继续。
