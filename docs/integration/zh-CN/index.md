# SRICH CHAT 对接总览：谁负责什么，按什么顺序接入

这份公开对接指南写给买方开发与运营。SRICH CHAT 提供会员聊天页、客服工作台、管理后台与服务运行能力；你们保留网站登录、业务数据、业务规则和最终写入权。

## 九个对接点，三个主要方向

| 对接点 | 谁调谁 | 用途 |
| --- | --- | --- |
| 页面嵌入 | 网站加载聊天启动器 | 把聊天放进现有网站 |
| 会员身份 | 后端签名或后端换票 | 让聊天认识当前会员 |
| 事件 | 买方服务器调用客服系统 | 按事件模板发聊天卡片 |
| 邮箱 | 买方服务器调用客服系统 | 给指定会员写通知或汇总 |
| 信息 | 后端发数据，网站接实时回调 | 页面时效信息 |
| 红包通信 | 事件通知与网站读取配置 | 传递活动信息，业务仍在买方 |
| FAQ 源 | 客服系统读取买方接口 | 同步有效知识内容 |
| 看板 | 客服系统读取买方接口 | 客服与会员查询业务数据 |
| 操作 | 客服系统调用买方接口 | 发起经授权的业务动作 |

先完成页面与可信身份，验收登录、退出、恢复和重连，再按需求增加其余接口。查询不是另一套数据源：先有看板，运营再开放给会员。

## 凭据与接口的责任

站点凭据和签名私钥只保存在买方后端；不要写进网页、URL、截图或日志。调用买方接口的地址与钥匙按站点和用途配置，不能把 A 站会员发给 B 站接口。

客服系统对外响应采用 `code / message / data / request_id` 信封。买方提供的 FAQ、看板、操作各有自己的响应契约，不能把这一信封硬套给所有方向。错误分支看 `code`，排查保留 `request_id`，不要靠匹配文案。

金额按具体接口：看板与业务操作通常使用最小单位整数；信息与红包展示金额使用十进制字符串，不能混用。时间使用 Unix 秒。

## 最小验收

同一个会员重新认证后回到同一会话，换人登录看不到前一人的记录。持续会话不等于消息一直保留：默认启用 30 天清理，按实际配置保存。完成基础验收后，再测各业务接口的成功、拒绝、超时、重复与越权情况。

本系列是公开版接入说明与验收指南，不包含产品源码、生产配置或真实凭据。完整字段限制和对应版本变更见帮助中心。
